# 前端 UI 自我审查与审美机制

> **A级文档** — 前端 UI 的动态化、自我审查与审美对标总纲。
> 任何 AI 代理在变更 UI（HTML / CSS / Canvas 渲染 / 弹窗文案 / HUD 数值）前必须阅读本文档。
> 违反"动态化强制清单"或"自我纠错触发条件"任一条，视为 P0 级错误。

> **用户原话：** "所有的前端都不能是硬编码，必须动态，必须有自我审查和审美机制，根据市面上的大游戏即时调整 UI，否则每次变更都需要我提醒。"

---

## 一、核心原则

### 1. 数据驱动（Anti-Hardcode）

- 所有数值、文案、数量、卡片数、列表项数必须从 `js/data.js` 常量动态读取。
- HTML 中禁止出现具体业务数字（如"20 章""18 角色""3 难度"），必须改用模板字符串 / JS 注入。
- 仅允许硬编码的内容：DOM 骨架标签、CSS 类名、加载顺序、纯展示性占位符（`__placeholder__`）。
- 新增可枚举内容（模式 / 难度 / 让子 / B王层数等）必须先在 `data.js` 建常量，再由 JS 渲染。

### 2. 自我审查（Self-Audit）

- 每次 UI 变更后，必须按"[[#三、UI 审查清单]]"逐项检查，不得跳过。
- 审查结果应在 `项目修改记录.md` 的对应版本条目中留下"已通过 UI 自审"标记。
- 未跑自审的 UI 改动不得视为完成。

### 3. 审美对标（Aesthetic Benchmarking）

- 参考市面大游戏与大产品的水墨 / 古风 / 极简美学，参见"[[#四、大游戏审美参考库]]"。
- 不照抄视觉元素，只借鉴**配色逻辑 / 留白比例 / 层级关系 / 动效节奏 / 图标语义**。
- 每次重大 UI 迭代前，AI 须主动检索 1–2 款参考产品的最新视觉语言，与当前实现做差异比对。

### 4. 主动维护（Proactive Maintenance）

- AI 检测到 UI 问题时**主动修复**，不等用户提醒。
- 触发条件见"[[#五、自我纠错触发条件]]"，命中任一条即进入修复流程。
- 修复后必须在 `项目修改记录.md` 记录"主动纠错：xxx"，便于追溯 AI 的自愈行为。

## 二、动态化强制清单

> 以下字段必须由代码动态生成。出现硬编码即触发"[[#五、自我纠错触发条件]]"第 2 条。

| 字段 | 数据来源 | 禁止示例 | 正确示例（语义） |
|------|---------|---------|----------------|
| 故事章节数 | `STORY_CHAPTERS.length` | `共20章` | `共 ${STORY_CHAPTERS.length} 章` |
| 角色数 | `Object.keys(CHARACTERS).length` | `18位武将` | `${Object.keys(CHARACTERS).length} 位武将` |
| 角色主动技能数 | `ch.actives.length` | `3个主动技能` | `${ch.actives.length} 个主动技能` |
| 角色被动技能数 | `ch.passives.length` | `2个被动` | `${ch.passives.length} 个被动` |
| 游戏模式数 | `MODES` 常量（**需新建**） | `6种模式` | `${MODES.length} 种模式` |
| 难度数 | `Object.keys(DIFFICULTIES).length` | `3难度` | `${Object.keys(DIFFICULTIES).length} 难度` |
| 让子数 | `HANDICAPS` 常量（**需新建**） | `4档让子` | `${HANDICAPS.length} 档让子` |
| B王层数 | `Object.keys(BKING_LAYERS).length` | `7层` | `${Object.keys(BKING_LAYERS).length} 层` |
| B王主动技能数 | `CHARACTERS.bking.actives.length` | `5个主动` | `${CHARACTERS.bking.actives.length} 个主动` |
| 新手教程步数 | `TUTORIAL_STEPS.length` | `12步教程` | `${TUTORIAL_STEPS.length} 步教程` |
| 兵种数 | `Object.keys(PIECE_STATS).length` | `7种棋子` | `${Object.keys(PIECE_STATS).length} 种棋子` |
| 棋子属性数值 | `PIECE_STATS[k].hp/atk/def` | `帅血量260` | `${PIECE_STATS.k.hp}` |
| 技能描述中的数值 | 从 `game.js` case 分支提取 | `造成40真伤` | `造成 ${DMG.IMMORTAL_JUDGE} 真伤` |
| 模式卡片列表 | 遍历 `MODES` 渲染 | HTML 写死 6 张卡片 | JS `forEach` 注入 |
| 难度卡片列表 | 遍历 `DIFFICULTIES` 渲染 | HTML 写死 3 张卡片 | JS `forEach` 注入 |
| 选将屏被动提示 | `passives.length > 2 ? '选2个' : '选1个'` | 硬编码"二选一" | 动态判断（参见 [[HARD_CONSTRAINTS#U5]]）|

**待新建常量：**

- `MODES`：游戏模式枚举（PVE / PVP / 故事 / 阵营 / 三英战B王 / 4v4）
- `HANDICAPS`：让子档位枚举
- `BKING_LAYERS`：B王层数枚举（如对应七宗罪）
- `TUTORIAL_STEPS`：新手教程步骤数组（如已存在则改为单一数据源）

## 三、UI 审查清单（每次 UI 变更后必跑）

> 三类检查，每类逐项过。任一未通过即返回修复，不得放行。

### 1. 一致性检查（Consistency）

- [ ] HTML 显示数字与 `data.js` 常量计算结果一致
- [ ] 技能描述文案与 `game.js` case 分支数值一致
- [ ] 模式 / 难度 / 让子卡片数量与对应常量 `.length` 一致
- [ ] 新手教程步数与 `TUTORIAL_STEPS.length` 一致
- [ ] 选将屏"选 N 个"提示与 `passives.length` 判断逻辑一致
- [ ] 文档（AGENTS.md / HARD_CONSTRAINTS.md / SKILL_RAG.md）中的数字与代码同步
- [ ] HUD 显示的角色属性与 `CHARACTERS[id].stats` 一致
- [ ] 棋子血条数值与 `PIECE_STATS[type].hp` 一致

### 2. 审美检查（Aesthetics）

- [ ] **配色协调**：水墨主色 + 单一强调色，无超过 3 种饱和色并存
- [ ] **留白合理**：模块间距 ≥ 模块内 padding，避免信息密度过高
- [ ] **层级清晰**：标题 / 正文 / 辅助文案字号比 ≥ 1.4 / 1 / 0.85
- [ ] **动效流畅**：进入 / 离开 / 状态切换均有过渡，时长 200–400ms，缓动函数一致
- [ ] **图标不 low**：SVG 图标线宽统一（建议 1.5–2px），无像素风与扁平风混用
- [ ] **字体一致**：标题用书法 / 衬线体，正文用无衬线体，不混用 3 种以上字体
- [ ] **阴影克制**：最多 2 层阴影，方向统一（建议单一光源 45° 顶光）
- [ ] **对齐严格**：所有卡片网格按 8px 基线对齐，无 1px 错位
- [ ] **水墨主题统一**：边框 / 背景 / 装饰元素符合水墨语言，无突兀的扁平色块

### 3. 可用性检查（Usability）

- [ ] **响应式**：1024 / 1280 / 1440 / 1920 四档分辨率下无溢出、无遮挡
- [ ] **无障碍**：所有可点击元素键盘可达，焦点态可见，对比度 ≥ AA 级
- [ ] **操作流畅**：点击 → 反馈延迟 < 100ms，无卡顿感
- [ ] **反馈及时**：技能释放 / 移动 / 吃子均有视觉 + 听觉双反馈
- [ ] **错误提示**：非法操作有 toast / 浮层提示，不静默失败
- [ ] **加载态**：异步操作有 loading 占位，不出现空白闪烁
- [ ] **撤销路径**：危险操作（保存覆盖 / 重新开始）有二次确认
- [ ] **移动端可用**（如适用）：触控热区 ≥ 44×44px

## 四、大游戏审美参考库

> 每次重大 UI 迭代前，AI 须从此库挑选 1–2 款作为对标，做差异比对后再动手。

### 1. 《逸剑风云诀》（水墨武侠 RPG）

- **参考维度**：配色 / 字体 / 装饰元素
- **借鉴点**：墨色渐变背景 + 朱砂红强调色；标题用书法体，正文用宋体；边角处水墨晕染笔触装饰
- **在本项目中的应用方向**：棋盘外框、选将屏背景、章节标题装饰采用同款水墨晕染；技能释放特效参考其笔触动画

### 2. 《月之暗面 Kimi 官网》（极简 AI 产品）

- **参考维度**：留白 / 排版 / 字号层级
- **借鉴点**：超大留白比例（模块间距 ≈ 模块高度 50%）；黑白灰三色为主；标题与正文字号差异极大（≈2.5 倍）
- **在本项目中的应用方向**：主菜单 / 模式选择页采用同款大留白；HUD 状态栏简化为单行高对比文字

### 3. Apple Design Awards 获奖应用（年度设计标杆）

- **参考维度**：动效 / 阴影 / 无障碍
- **借鉴点**：spring 动效曲线；多层柔和阴影（ambient + key）；VoiceOver 完整支持；动态字号
- **在本项目中的应用方向**：棋子移动 / 吃子动效采用 spring 曲线；弹窗阴影改为双层柔和阴影；HUD 文字支持系统级动态字号

### 4. Notion（极简文档工具）

- **参考维度**：图标系统 / 配色克制 / 内容优先
- **借鉴点**：单色线性图标，线宽 1.5px 统一；中性灰阶 9 级；强调色仅一种（黑）
- **在本项目中的应用方向**：技能图标 / 模式图标统一为单色线性 SVG；UI 配色收敛为"墨黑 + 朱砂 + 9 级灰"

### 5. Linear（开发者工具）

- **参考维度**：动效节奏 / 状态反馈 / 暗色模式
- **借鉴点**：所有过渡 200ms ease-out；hover 态轻微亮度提升（+8%）；键盘快捷键全覆盖
- **在本项目中的应用方向**：所有按钮 / 卡片 hover 统一 200ms ease-out；增加键盘操作（如 1-9 选技能）；暗色主题作为默认

### 6. Vercel Dashboard（数据可视化）

- **参考维度**：数据卡片 / 状态徽标 / 信息密度
- **借鉴点**：数据卡片左对齐 + 右上角状态点；关键数字超大字号；次要信息折叠
- **在本项目中的应用方向**：角色属性面板（atk/def/int）采用同款卡片布局；战斗日志采用折叠式时间线

### 7. 《原神》UI（二次元大作）

- **参考维度**：技能图标 / 元素配色 / 弹窗层级
- **借鉴点**：技能图标圆角矩形 + 元素色边框；弹窗多层级蒙层（背景模糊 + 局部高亮）；星级视觉权重
- **在本项目中的应用方向**：技能图标统一为圆角矩形 + 阵营色边框；选将弹窗采用背景模糊 + 局部高亮；角色稀有度用星级表达

### 8. 《崩坏：星穹铁道》UI（回合制大作）

- **参考维度**：回合制战斗 UI / 状态条 / 技能释放面板
- **借鉴点**：底部技能面板固定布局，技能图标 + CD + 描述三段式；目标选中时金色脉冲高亮（4 秒）；buff 图标紧凑横排
- **在本项目中的应用方向**：底部技能释放面板对齐其三段式布局；技能目标高亮沿用金色脉冲（已见 [[HARD_CONSTRAINTS#U6]]）；buff 图标横排于棋子血条下方

## 五、自我纠错触发条件

> AI 在阅读 / 修改代码时命中以下任一条件，**必须主动**进入修复流程，不等用户提醒。

1. **代码数值与文档描述不一致**
   - 例：`PIECE_STATS.k.hp = 260` 但 AGENTS.md / HARD_CONSTRAINTS.md / SKILL_RAG.md 写的是 300
   - 动作：以代码为准，同步更新所有文档

2. **HTML 中出现具体业务数字而非模板字符串**
   - 例：`<div>共 20 章</div>`、`<span>18 位武将</span>`
   - 动作：改为 JS 动态注入，数字从 `data.js` 常量读取

3. **技能描述与 case 分支数值不符**
   - 例：描述写"造成 40 真伤"，`game.js` case 分支实际是 60
   - 动作：以 case 分支为准，更新描述；或反之，但必须双向同步

4. **模式 / 难度 / 让子卡片数量与常量不一致**
   - 例：`MODES.length === 6` 但 HTML 只渲染了 5 张卡片
   - 动作：改为遍历 `MODES` 动态渲染

5. **新手教程数值与实际代码不同步**
   - 例：教程说"7 步学会"，但 `TUTORIAL_STEPS.length === 12`
   - 动作：以 `TUTORIAL_STEPS.length` 为准，更新教程文案

6. **选将屏被动提示硬编码**
   - 例：硬编码"二选一"但 `passives.length > 2`
   - 动作：改为动态判断（参见 [[HARD_CONSTRAINTS#U5]]）

7. **视觉风格与水墨主题冲突**（审美触发）
   - 例：新增扁平高饱和色块、像素风图标混入
   - 动作：替换为水墨语言元素，对照"[[#四、大游戏审美参考库]]"

8. **动效缺失或不一致**（审美触发）
   - 例：新增弹窗无过渡、hover 态无反馈、缓动函数不统一
   - 动作：补齐 200–400ms 过渡，统一缓动函数

### 触发时机

- AI 每次修改 UI 相关代码后（必跑[[#三、UI 审查清单]]）

- 用户提醒 UI 问题时（纳入本文档为新约束，参见 [[HARD_CONSTRAINTS#3. 用户提醒纳入约束]]）

- 违反"[[#二、动态化强制清单]]" → P0 级，必须立即修复
