# 防幻觉审查清单

> **A级强制清单** — 每次代码改动前/后必须逐项检查并打勾。
> 任何一项未通过，禁止提交。

## 🔍 改动前检查（理解阶段）

### 1. 需求理解
- [ ] 我能用自己的话复述用户需求
- [ ] 我识别了用户的所有隐含要求（如"古文风格"=不提他人+古文用词）
- [ ] 我检查了用户历史提醒中是否有相关约束（[[HARD_CONSTRAINTS]]）
- [ ] 我确认了改动范围（哪些文件、哪些函数）

### 2. 现状调研
- [ ] 我已阅读相关代码（不只是搜索，而是完整阅读上下文）
- [ ] 我已检查所有使用相同关键词的位置（`grep -rn`）
- [ ] 我已确认当前实现与描述是否一致（如不一致，先记录）
- [ ] 我已识别所有可能受影响的下游模块

### 3. 设计决策
- [ ] 我已确认技能机制符合游戏机制（回合制/棋盘规则）
- [ ] 我已确认数值合理性（无100%血量取反之类的逻辑漏洞）
- [ ] 我已确认描述不提及无关角色
- [ ] 我已确认UI显示文案与实际选择数量一致

- [ ] 技能描述中的每个机制都与代码实现一致
- [ ] 技能描述中的触发条件都与代码实现一致
- [ ] 技能描述中的代价/限制都与代码实现一致

## 🚨 常见幻觉陷阱

### 陷阱1：描述写了一套，代码实现另一套
**症状：** 描述说"攻击+50%"，代码实际是"攻击+20%"
**防范：** 改动后逐字对照描述与代码数值

### 陷阱2：UI硬编码文案
**症状：** 被动5个但UI显示"二选一"
**防范：** 数量动态判断，禁止硬编码选择数量

### 陷阱3：机制与游戏机制冲突
**症状：** 回合制游戏写"自身无法行动"
**防范：** 机制设计前先问"这个机制在当前游戏框架下是否合理"

### 陷阱4：只改一处忘记关联处
**症状：** 改了技能名但没改case分支
**防范：** `grep -rn "旧名称"` 全项目扫描

### 陷阱5：声称已实现但实际未实现
**症状：** 被动技能在data.js定义了但skills.js无case实现
**防范：** 每个被动id必须有对应的triggerPassive case分支

### 陷阱6：数值不合理
**症状：** 100%血量取反仍100%
**防范：** 边界值测试（0%/50%/100%）

### 陷阱7：PVE有效但PVP无效
**症状：** 被动只在玩家方触发，黑方不触发
**防范：** 检查 `passivesApplyAuras` / `triggerPeriodicPassives` 是否按 currentPlayer 分发

### 陷阱8：buff只写不读
**症状：** 设置了 `state.xxx` 但从没读取
**防范：** 每个新state字段必须确认有读取位置

### 陷阱9：跨局残留
**症状：** 第二局首回合跳过播报或叠加层数异常
**防范：** `resetPassives()` 中重置所有运行时状态

### 陷阱10：AI模拟污染
**症状：** calcDamage中的随机闪避污染AI搜索结果
**防范：** `isAICombatSimulation` 标志隔离随机性
