# 硬约束总纲

> **A级约束** — 任何AI代理在修改本项目前必须阅读并遵守。
> 违反任意一条均视为P0级错误。

## 🔒 核心原则

### 1. 主动关联检查（注意力机制）

> **用户原话：** "我更改一个地方的时候，你要学会自己判断逻辑，以及自己学会去找可能相关的问题点，而不是我反复的提醒"

**强制行为：** 修改任何代码/数据时，必须主动扫描所有可能受影响的位置：

- 修改技能描述 → 检查 `data.js`、`game.js`（case分支）、`skills.js`（被动实现）、UI显示标题
- 修改buff类型 → 检查 `engine.js`（calcDamage）、`engine.js`（getPieceEffectiveStats）、UI显示
- 修改被动数量 → 检查选将屏渲染、`getActivePassives`、codex页面、教程文案、所有"选1"/"选2"硬编码文案
- 修改角色属性 → 检查 `PIECE_STATS`、`getCharBonus`、HUD显示、AI估值
- 修改技能机制 → 检查描述与实现是否一致、PVE/PVP/三英三种模式是否都生效

**检查清单：** 修改后必须执行 `grep -rn "关键词"` 扫描全项目相关位置。

### 2. 描述与实现一致性

> **用户原话：** "这种最基本的逻辑错误不要再出现了"

**强制行为：**
- 技能描述中的每个数字、机制、触发条件必须与代码实现完全一致
- 修改描述时同步修改实现；修改实现时同步修改描述
- 数值改动后必须更新描述中的对应数字

### 3. 用户提醒纳入约束

> **用户原话：** "你的注意力机制和强制约束，应该我每一次的提醒你都要纳入强制约束"

**强制行为：** 用户每次提醒的问题，必须：
1. 立即加入本文档对应章节
2. 标注为"用户提醒"（用户原话）
3. 在 `[[ANTI_HALLUCINATION]]` 检查清单中添加对应检查项
4. 后续所有变更都必须遵守

## 💻 工程约束

### 代码风格

- 使用 `'use strict';`
- 函数命名：`camelCase`
- 常量命名：`UPPER_SNAKE_CASE`
- 坐标：`{r, c}`（禁止 `{row, col}` 混用）
- 移动操作：`{from:{r,c}, to:{r,c}}`

### 模块职责（不可越界）

| 模块 | 职责 | 禁止 |
|------|------|------|
| `data.js` | 数据层 | 放逻辑 |
| `engine.js` | 棋盘逻辑/AI/伤害结算 | 操作state/UI |
| `skills.js` | 被动触发/主动技能扩展 | 渲染 |
| `game.js` | 状态管理/流程/渲染/UI | 放纯逻辑（应抽到engine）|

### 测试与验证

```bash
# 语法校验（每次修改必跑）
node -c js/data.js && node -c js/engine.js && node -c js/skills.js && \
node -c js/portrait.js && node -c js/audio.js && node -c game.js
```

### 版本规格文档

重大改动必须在 `.trae/specs/<version>/` 创建规格文档：
- `spec.md`：需求规格
- `tasks.md`：任务分解
- `checklist.md`：验证清单

## 🧠 AI协作流程

### 修改前必做

1. 阅读 [[AGENTS]]（项目根）
2. 阅读本文档
3. 阅读 [[ANTI_HALLUCINATION]]
4. 阅读相关模块文档（[[SKILL_RAG]] / [[ARCHITECTURE]]）
5. 阅读 `项目修改记录.md` 最新版本

### 修改后必做

1. 运行 `node -c` 校验所有修改的JS文件
2. 更新 `项目修改记录.md`（最新置顶）
3. 更新相关文档（如涉及技能/buff/架构变更）
4. 在 `[[ANTI_HALLUCINATION]]` 检查清单中打勾

### 代理协作流程

1. **阅读本文件** 了解项目约束
2. **阅读 `项目修改记录.md`** 了解历史改动
3. **阅读 `.trae/specs/` 最新版本** 了解当前任务
4. **修改前先创建规格文档**（如涉及重大改动）
5. **修改后更新 `项目修改记录.md`**
6. **运行 `node -c` 校验** 所有修改的JS文件

## 📌 历史教训（Lessons Learned）

| 问题 | 根因 | 防范 |
|------|------|------|
| 属性名不一致导致AI移动失败 | `to:{row,col}` vs `to:{r,c}` | 强制 `{r,c}` |
| 炮自杀 | calcDamage返回值应用反了 | 修改伤害结算时回归测试 |
| 棋子点击无响应 | 操作菜单拦截selectPiece | UI事件优先级审查 |
| 被动技能不生效 | case未补全 | 新增被动必须实现case |
| 选将技能选择无效 | 未读取state.playerActiveSkill | 选将→战斗数据流审查 |
| 被动显示"二选一"但实际5选2 | UI硬编码文案 | 数量>2时动态显示 |
| 因果逆转100%血量无效 | 机制与游戏机制冲突 | 机制合理性审查 |
| "自身无法行动"在回合制无意义 | 机制冲突 | 机制合理性审查 |
| 描述提及其他角色 | 文案风格不一致 | 古文风格+不提他人 |
